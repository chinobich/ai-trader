# 電話音声ブリッジ（PhoneBridge）

固定電話の音声をPCに取り込み、ヘッドセットで通話しながら、同じ音声を**マイクとしてAI基盤に渡す**Windows用ツールです。

以前のサービス（SoftVoice）では、PC上のソフトが「白い箱」と「ヘッドセット」の間で音を中継していました。このツールがその中継を代わりに行います。

```
[相手の声] 電話機 → 白い箱(録音側) → PhoneBridge ─┬→ ヘッドセット（耳）
                                                  └→ ┐
[自分の声] ヘッドセット（マイク） → PhoneBridge ─┬→ 白い箱(再生側) → 電話機
                                                  └→ ┤
                                                     ↓ 相手＋自分を1chにまとめる
                                 仮想ケーブル「CABLE Input」
                                                     ↓
                     Windows上のマイク「CABLE Output」 → AI基盤（仮想ブラウザ）
```

- AI基盤へは、相手の声と自分の声を**1chにまとめて**送ります。AI基盤が2chに対応したら、設定で「左＝相手／右＝自分」に切り替えられます。
- 追加で入れるソフトは **VB-CABLE**（無料の仮想オーディオケーブル）だけです。
- ツール自体は、Windowsに最初から入っているC#コンパイラで作れます。Pythonなどのインストールは不要です。

## 1. 用意するもの

| もの | 入手先 | 備考 |
|---|---|---|
| PhoneBridge.exe | 下の「2. 入手方法」 | インストール不要。フォルダに置くだけ |
| VB-CABLE | https://vb-audio.com/Cable/ | 管理者権限でインストール。業務での利用条件は配布元のサイトで確認してください |

## 2. 入手方法（AかBのどちらか）

### A. できあがった exe をダウンロードする

1. GitHub でこのリポジトリを開き、「Actions」→ 左の一覧から「PhoneBridge」を選ぶ
2. 一番上（最新）の実行結果を開く
3. 下の「Artifacts」にある **PhoneBridge** をダウンロードする（zip）
4. zip を展開すると `PhoneBridge.exe` が入っている

※ GitHub へのログインが必要です。保存期間は90日です。

### B. 端末の上でビルドする

1. このリポジトリの `phone_audio_bridge` フォルダ（`build.bat` と `src` フォルダ）を端末にコピーする
2. `build.bat` をダブルクリックする
3. 同じフォルダに `PhoneBridge.exe` ができる

## 3. 初回セットアップ（1回だけ）

1. **以前のサービスのソフトを終了する**
   - タスクトレイに残っていないか、スタートアップに登録されていないかも確認してください。
   - 動いたままだと、白い箱を独占されてこのツールが使えません。
2. **VB-CABLE をインストールする**
   - zip を展開し、`VBCABLE_Setup_x64.exe` を右クリック →「管理者として実行」→「Install Driver」
   - 終わったらPCを再起動します。
3. **Windowsのサウンド設定を確認する**（Win+R で `mmsys.cpl`）
   - 「再生」タブ：既定のデバイスがヘッドセット（またはPCのスピーカー）になっていること。
     **「CABLE Input」が既定になっていたら戻してください。** そのままだと、PCのすべての音がAI基盤に流れます。
   - 「録音」タブ：同じく、既定のデバイスが「CABLE Output」になっていないこと。
   - 「通信」タブ：「何もしない」を選ぶ。
   - 白い箱とヘッドセットの各マイクの「プロパティ」→「聴く」タブ：「このデバイスを聴く」がオフになっていること。
4. **マイクの利用を許可する**
   - Windowsの設定 → プライバシーとセキュリティ → マイク →「デスクトップアプリがマイクにアクセスできるようにする」をオンにします。
5. **PhoneBridge.exe を起動し、「機器の設定」タブで5つを選ぶ**

   | 項目 | 選ぶもの（例） |
   |---|---|
   | 電話の音（白い箱のマイク側） | マイク (USB Audio Device) など |
   | 電話へ送る音（白い箱のスピーカー側） | スピーカー (USB Audio Device) など |
   | ヘッドセットのマイク | いつものヘッドセットのマイク |
   | ヘッドセットのスピーカー | いつものヘッドセット |
   | AI基盤へ送る先 | CABLE Input (VB-Audio Virtual Cable) |

6. **「通話」タブで「▶ 開始」を押し、テスト通話をする**
   - 相手の声がヘッドセットで聞こえるか、こちらの声が相手に届くかを確認します。
   - 通話は、以前と同じ手順で始めてください（電話機の操作は変わりません）。
7. **AI基盤（仮想ブラウザ）のマイクで「CABLE Output (VB-Audio Virtual Cable)」を選ぶ**

### どれが白い箱か分からないとき

- とりあえず選んで「▶ 開始」を押し、「通話」タブのメーターを見ます。
  - ヘッドセットに向かって話すと「自分の声」が動きます。
  - 通話中に相手が話すと「相手の声」が動きます。
- 白い箱とヘッドセットが同じような名前で区別しにくい場合は、`mmsys.cpl` で機器を選んで「プロパティ」から名前を変えておくと分かりやすくなります（例：「電話BOX」）。
- USBの挿し口を変えても、ツールは同じ機器を自動で見つけ直します。

## 4. 毎日の使い方

- PhoneBridge.exe を起動して「▶ 開始」を押します。止めるときは「■ 停止」か、ウィンドウを閉じます。
- 「音量・音質」タブで「起動したら自動で開始する」にチェックを入れると、起動するだけで動きます。
- **PCの起動時に自動で起動する**には、Win+R で `shell:startup` を開き、PhoneBridge.exe のショートカットを置きます。
  - ショートカットのプロパティで「リンク先」の最後に ` /start /min` を付けると、最小化した状態で自動で開始します。
- 通話中にUSBが抜けても、つなぎ直せば2秒ほどで自動的に再開します。

## 5. 画面の説明

| タブ | 内容 |
|---|---|
| 通話 | 開始／停止、マイクのミュート、録音、音量メーター、各機器の状態 |
| 機器の設定 | 5つの機器の割り当て（停止中のみ変更可） |
| 音量・音質 | 下の表を参照 |
| ログ・診断 | 動作の記録、診断情報の保存、フォルダを開くボタン |

「音量・音質」タブの項目：

| 項目 | 説明 |
|---|---|
| 相手の声の大きさ | ヘッドセットで聞こえる相手の声の音量 |
| 自分の声の大きさ | 相手に届く自分の声の音量 |
| AI基盤へ：相手の声／自分の声 | AI基盤に送る音のバランス（自動調整の後にかかります） |
| AI基盤へ送る音量を自動でそろえる | 小さい声を持ち上げ、大きい声を抑えます。**オン推奨** |
| AI基盤へ送る相手側の音を下げる | 自分の発言が、相手の発言としても二重に文字起こしされるときにオン |
| ヘッドセットの相手側の音を下げる | 自分の声が少し遅れて聞こえて話しにくいときにオン |
| AI基盤へ2chで送る | AI基盤が2chに対応してから使います（左＝相手、右＝自分） |
| マイクをミュート | 自分の声を、相手とAI基盤の両方に送らなくなります |
| 通話を録音する | 「録音フォルダ」に WAV（左＝相手、右＝自分）で保存します。初期状態はオフ |

電話機は、自分の声を受話音に少し混ぜて返してきます（側音）。上の「…音を下げる」の2項目は、この側音への対策です。気にならなければオフのままで構いません。

## 6. 困ったとき

| 症状 | 確認すること |
|---|---|
| 相手の声が聞こえない | 「相手の声」メーターが動くか。動かなければ「電話の音」の選択を確認し、以前と同じ手順で通話を始めているかを確認。動くのに聞こえなければ、「ヘッドセットのスピーカー」の選択とWindowsの音量を確認 |
| 相手にこちらの声が届かない | 「自分の声」メーターが動くか、ミュートになっていないか、「電話へ送る音」の選択、「自分の声の大きさ」 |
| AI基盤に音が入らない | 「AI基盤へ送っている音」メーターが動くなら、AI基盤側のマイクが「CABLE Output」になっているか、仮想ブラウザのマイク許可を確認。動かなければ「AI基盤へ送る先」が「CABLE Input」か |
| 状態に「他のソフトがこの機器を独占しています」 | 以前のサービスのソフトなど、白い箱を使っているソフトを終了する |
| 状態に「アクセスが拒否されました」 | 「3. 初回セットアップ」の手順4（マイクの許可） |
| 状態に「見つかりません」 | USBの接続を確認する。つながると自動で再開します |
| 音がブツブツ途切れる | 診断情報を保存して送ってください。応急処置として、PhoneBridge.ini の `LinkTargetMs=30` を `60` にすると改善することがあります（遅延は少し増えます） |
| PCの通知音などがAI基盤に入る | 「3. 初回セットアップ」の手順3（既定のデバイスが CABLE Input になっていないか） |

### 診断情報の送り方

「ログ・診断」タブの「**診断情報を保存**」を押すと、テキストファイルが作られます（クリップボードにもコピーされます）。中身は、機器の一覧・音声形式・設定・動作状況です。通話の内容は含まれません。

## 7. 詳しい設定（PhoneBridge.ini）

設定は exe と同じフォルダの `PhoneBridge.ini` に保存されます。そのフォルダに書き込めない場合は `%LOCALAPPDATA%\PhoneBridge` に保存されます。通常は画面から変更すれば十分です。

| 項目 | 初期値 | 説明 |
|---|---|---|
| LinkTargetMs | 30 | 機器の間で溜めておく音の長さ(ms)。大きくすると途切れにくく、遅延は増える |
| RenderTargetMs | 20 | 再生機器に先に渡しておく音の長さ(ms) |
| DuckThresholdDb | -34 | 「自分が話している」と判断するマイクの音量(dBFS) |
| DuckDepthDb | -15 | 自分が話している間に相手側の音を下げる量(dB) |
| RecordDir | （空） | 録音の保存先。空なら exe の場所の `recordings` フォルダ |

片道の遅延の目安は、上の2つの合計に機器側のバッファを足した値（初期値でおよそ50〜70ms）です。

## 8. 注意事項

- 録音ファイルには通話の内容（個人情報）が含まれます。保存場所と保存期間は、所属のルールに従って管理してください。
- 通話の内容をAI基盤で扱うことについて、所属のルールや、相手への告知が必要かどうかを確認してください。
- 白い箱がSoftVoiceの貸与品であれば、サービスをやめた後も使えるかどうか、契約を確認してください。

## 開発者向けメモ

- `src/Wasapi.cs` … Windows の音声API（WASAPI）の呼び出し、機器の一覧、音声形式の変換
- `src/Dsp.cs` … サンプリング周波数の変換、機器間の時計のずれの補正、自動音量調整、側音対策、WAV書き出し
- `src/Engine.cs` … 機器ごとのスレッド、配線、自動再接続、診断情報
- `src/MainForm.cs` … 画面（WinForms）
- `src/SelfTest.cs` … `PhoneBridge.exe /selftest [ログ]`（音声処理だけのテスト。機器は不要）と、`PhoneBridge.exe /devicetest [ログ]`（VB-CABLE に音を流して録り直す実機テスト）
- コードは、Windows 標準の C# コンパイラ（C# 5）で通る書き方に限定しています。
- CI（`.github/workflows/phone-audio-bridge.yml`）：Windows 上でビルド・自己テストを行い、exe を Artifacts に保存します。別のジョブで VB-CABLE を入れて実機テストも行います。
